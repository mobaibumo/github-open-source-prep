# 按项目类型整理

## 代码
保留源码、依赖清单及适用锁文件、构建配置、必要测试和示例。缓存、虚拟环境、依赖安装目录和可再生构建结果一般忽略；静态站发布等情况结合现有工作流判断。配置示例只含占位值，保留变量名和解释。

## Codex Skill
保持 SKILL.md、被引用的 references、scripts 和运行必需 assets 完整。检查相对路径、工具依赖、运行环境、安装位置和调用示例。不把作者个人绝对路径固化为使用要求。用户要求将 Skill 自身作为开源项目交付时，为该项目生成双语 README；不要把一般项目的开源文档要求套到所有内部 skill 资源中。

## 设计素材与产品图片
区分可编辑源文件、原始参考、过程稿、最终成品、精选示例和缩略预览；这是内容分类，不强制创建这些目录。默认仅上传必需内容和精选示例，保留原件在本地。若项目价值就是可编辑模板或源素材，源文件可能是必需交付物，按用户意图确认。

记录实际格式、尺寸、软件版本（可获知时）、使用方法、素材来源及授权范围。不得把第三方参考图或客户资料默认当作可再分发资产。仅在确有需要时清理公开导出件元数据，保留原件。

较大资产根据使用方式选择：仓库保留轻量预览；需要版本管理且环境支持时考虑 Git LFS；发行包可用 Release 附件。先核对 GitHub 当前限制、LFS 配额及可用性，再建议方案。不要自动把全部二进制迁入 LFS 或重写历史。

## 混合项目
保留统一首页，说明代码、Skill 和资产之间的关系及各自入口。按子目录声明不同许可证时核对边界与原始声明。不要把同一个素材复制到多个目录以满足模板。
